### Added

- `Flow.IoError` — `IoError` and `IoErrorKind`, the shared error type for
  recoverable I/O (proposal 0178, item 1). Fallible operating-system
  operations report failure as `Result<a, IoError>`, where `IoError` carries a
  machine-readable `kind` alongside a human-readable message and the path the
  operation was attempted on.

  `IoErrorKind` covers `NotFound`, `PermissionDenied`, `AlreadyExists`,
  `NotADirectory`, `IsADirectory`, `DirectoryNotEmpty`, `Interrupted`, and
  `Other`. Helpers: `io_error`, `io_error_no_path`, `error_kind`,
  `error_message`, `error_path`, `is_not_found`, `is_permission_denied`,
  `is_already_exists`, `is_retryable`, `kind_name`, `describe`.

  The structured `kind` is what makes these errors recoverable rather than
  merely reportable: callers branch on it, so `message` never becomes a
  compatibility surface. The type lives in its own module because
  `Flow.Fs`, `Flow.Crypto`, `Flow.Env`, and `Flow.Process` all report failures
  the same way — callers match one error type regardless of which capability
  produced it.

### Fixed

- The `flux --test` runner now records record-style constructor field order
  for every module it compiles, so a test file can use named-field syntax for
  a constructor declared in an imported module. Previously `--test` failed
  with a bogus arity mismatch (E082 / E085) where `flux run` succeeded, because
  the test runner compiles every module through one `Compiler` without the
  dependency preload the `run` drivers perform.
